# Получение и подключение IPA

Пайплайн работает на VPS. Задача выбирает приложение и профиль Apple Account; загрузчик использует отдельную сессию выбранного профиля. Получение файла и включение его в продажу — отдельные действия оператора.

## Компоненты

- `appki-acquirer` — отдельный системный пользователь и приватный CLI `appki-acquire`.
- `/var/lib/appki-acquirer` — закрытые профили, ключи хранилища, сессии и SQLite-очередь. Веб-сервис сюда не имеет доступа.
- `/var/lib/appki/artifacts` — проверенные неизменяемые IPA и общий реестр. Группа `appki-artifacts` даёт веб-сервису доступ на чтение; загрузчик не состоит в группе `appki` и не получает доступ к платёжным настройкам.
- `backend/appki/catalog.json` — исходные карточки каталога. Операторские настройки приложений и выбранные релизы хранятся в реестре вне Git.
- `/etc/appki/activation-profiles.json` — необязательные отдельные профили покупательской активации. Авторизация ipatool сюда автоматически не копируется.

## Установка инструмента

```sh
sudo bash /opt/appki/current/scripts/install-ipa-loader.sh
sudo -u appki-acquirer /usr/local/bin/appki-acquire status
```

Установщик собирает адаптер из закреплённого исходного кода ipatool и отдельного проверенного Go toolchain. Он не входит в Apple Account, не приобретает лицензии и не скачивает приложения.

Для сборки на Ubuntu нужны `gcc`, `libc6-dev`, `curl` и `patch`. Go устанавливается отдельно для загрузчика.

Адаптер использует файловое хранилище конкретного профиля, отдельный XDG-каталог и защищённый файл passphrase. Пароли и коды не передаются через аргументы процесса. Общие Secret Service и старый `~/.ipatool` не используются.

## Аккаунты

```sh
sudo -u appki-acquirer /usr/local/bin/appki-acquire profiles add catalog-1 --label 'Каталог 1'
sudo -u appki-acquirer /usr/local/bin/appki-acquire profiles login catalog-1
sudo -u appki-acquirer /usr/local/bin/appki-acquire profiles list
```

Вход выполняется оператором в терминале SSH. Apple Account, пароль и при необходимости 2FA вводятся интерактивно. После успешного входа профиль закрепляется за полученной идентичностью аккаунта; использовать тот же ID для другого Apple Account нельзя.

Одна блокировка профиля охватывает вход, обновление сессии и скачивание. Разные профили могут работать параллельно. 2FA загрузчика относится к операторскому входу, а не к коду активации приложения покупателя.

## Задачи и импорт

После настройки App Store ID и ожидаемого bundle ID задача принимает приложение и аккаунт:

```sh
sudo -u appki-acquirer /usr/local/bin/appki-acquire apps list
sudo -u appki-acquirer /usr/local/bin/appki-acquire apps configure v2raytun --app-store-id APP_STORE_ID --bundle-id BUNDLE_ID --price-rub 490
sudo -u appki-acquirer /usr/local/bin/appki-acquire jobs enqueue --app-slug v2raytun --account catalog-1
sudo -u appki-acquirer /usr/local/bin/appki-acquire jobs run JOB_ID
sudo -u appki-acquirer /usr/local/bin/appki-acquire jobs list
```

До заполнения метаданных доступны явные параметры `--app-store-id`, `--bundle-id` и `--title`. Значения нужно брать у выбранного приложения в App Store, а не угадывать по названию.

Для ручной приёмки файла доступна команда `import SOURCE.ipa --app-slug SLUG --bundle-id BUNDLE_ID --title TITLE --source-account ACCOUNT_ID --activation-profile PROFILE_ID`. Она выполняет те же проверки и не публикует приложение.

Загрузчик скачивает приложение, уже доступное аккаунту по лицензии. Он не инициирует платные покупки. Успех подтверждается ответом загрузчика и проверкой полученного IPA; нулевой код выхода команды авторизации сам по себе недостаточен.

Задача проходит состояния `queued`, `running`, `downloaded`, `ready`; ошибки и запрос входа переводят её в `failed`, `requires_auth` или `requires_2fa`. После подтверждения входа тот же ID задачи можно запустить повторно. Уже завершённая задача сохраняет прежний результат.

Реестр сохраняет приложение, bundle ID, версию, сборку, размер, SHA256, аккаунт получения и профиль активации. IPA хранится отдельно по приложению и хешу. Повторный импорт не перезаписывает файл. Одинаковая версия, полученная разными аккаунтами, сохраняет отдельное происхождение.

## Публикация и выдача

После проверки установки и запуска на iPhone оператор включает конкретный артефакт:

```sh
sudo -u appki-acquirer /usr/local/bin/appki-acquire publish v2raytun ARTIFACT_ID
```

Скачивание и импорт не снимают «Скоро» автоматически. Публичный каталог отдаёт только пользовательские поля; серверные пути, профили и данные загрузчика в API не попадают.

При первой выдаче позиция оплаченного заказа закрепляется за конкретным артефактом. Установочная ссылка и профиль активации используют эту привязку. Публикация новой версии не меняет файл у уже выданной ссылки или аккаунт активации старой выдачи. Старые файлы автоматически не удаляются.

## Совместимость

Существующие покупки Happ, суммы и отметки установки сохраняются. Первоначальный Happ зарегистрирован как legacy-артефакт; неизвестное происхождение не подменяется вымышленным аккаунтом. Его активация использует прежние настройки.

Новый артефакт без отдельного профиля активации использует ручную инструкцию и не наследует реквизиты legacy-аккаунта. Профиль с реквизитами должен явно указывать `account_id`, совпадающий с аккаунтом получения IPA; он выдаётся только владельцу подтверждённой покупки.

Для резервирования нужны SQLite Appki, реестр и архив IPA, приватное хранилище загрузчика и отдельный файл профилей активации. Резервные копии, содержащие авторизацию, требуют тех же ограничений доступа, что и исходное хранилище.

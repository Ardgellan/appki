# Аппки

Telegram-бот и Mini App с каталогом iPhone-приложений, оплатой через ЮKassa и выдачей временных ссылок установки. Первая версия работает с одним проверенным файлом Happ 5.9.0.

## Что реализовано

- Мобильный каталог, карточка приложения, заказы, установка и помощь.
- Вход через проверенную на сервере подпись Telegram Mini App.
- ЮKassa: создание заказа, внешний checkout, проверка статуса через API, уведомления об оплате и полном возврате.
- Доступ выдаётся только владельцу оплаченного заказа. Возврат закрывает новые установки; уже установленное приложение удалённо не удаляется.
- HTTPS-страница Safari → системная установка iOS → инструкция активации. Оригинальный IPA не изменяется и не переподписывается.
- Ссылки действуют час; новые доступны в оплаченном заказе. Поддержаны HEAD и Range для загрузки iPhone.
- Отдельный бот с командами, кнопкой Mini App и сохранением позиции обработки сообщений.
- Развёртывание на существующем VPS: nginx, systemd, отдельный пользователь, SQLite и TLS.

## Подключение аккаунтов

Заполните локальную `.env` (создаётся из `.env.example`):

| Поле | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен своего бота из BotFather |
| `BOT_USERNAME` | Username этого же бота, без `@` |
| `SUPPORT_URL` | Ссылка Telegram на поддержку |
| `YOOKASSA_SHOP_ID` | ID тестового магазина |
| `YOOKASSA_SECRET_KEY` | Секретный ключ тестового магазина, начинается с `test_` |

`YOOKASSA_MODE=test` и цена `1.00` оставлены для проверки. Без токенов каталог доступен для просмотра, вход и покупка отключены. Пустые значения не заменяются демонстрационными аккаунтами или фиктивной оплатой.

В кабинете ЮKassa добавьте адрес уведомлений:

```
https://85.239.144.214/api/payments/yookassa/webhook
```

События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Даже без уведомления открытая карточка заказа проверяет ожидающий платёж через API. Сам переход на страницу «оплата завершена» не выдаёт доступ.

Бот после запуска сам задаёт команды и кнопку меню. В BotFather можно дополнительно настроить Main Mini App на `https://85.239.144.214/`. Если у бота уже есть чужой webhook, обработчик откажется его перезаписывать; для проекта используйте своего отдельного бота.

## Локальная разработка

Требуются Python 3.11+ и Node 22+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e './backend[test]'
cd web
npm ci
npm run build
cd ..
```

Серверные пути из `.env` при локальном запуске нужно переопределить:

```sh
DATABASE_PATH=./work/dev.sqlite3 STATIC_DIR=./web/dist HAPP_IPA_PATH=/absolute/path/Happ.ipa \
  .venv/bin/python -m uvicorn appki.main:create_app --factory --host 127.0.0.1 --port 18880 --no-access-log
```

Для разработки frontend: `cd web && npm run dev`. Vite перенаправляет `/api` на локальный backend. В обычном браузере работает просмотр каталога; проверяемый вход появляется только при запуске из Telegram.

## Проверки

```sh
cd backend
../.venv/bin/python -m pytest -q
cd ../web
npm run build
```

Тесты используют отдельную временную базу, синтетический IPA и поддельный транспорт API. Они не списывают деньги, не отправляют сообщения и не используют `.env` владельца. Реальный платёжный цикл проверяется отдельно после подключения тестового магазина.

## Развёртывание

```sh
./scripts/deploy.sh
```

Скрипт собирает интерфейс, запускает тесты, передаёт код и закрытую `.env` через SSH, запускает службы и проверяет HTTPS. Настроен для `root@85.239.144.214` и существующего IP-сертификата Let's Encrypt. Для другого домена сначала обновите `PUBLIC_BASE_URL` и nginx/TLS.

`.env`, IPA, базы, ключи и зависимости исключены из Git. Архив релиза формируется по списку разрешённых путей; `.env` передаётся отдельно и хранится с ограниченными правами. На сервере используются `/opt/appki/current`, `/etc/appki/appki.env`, `/var/lib/appki/`.

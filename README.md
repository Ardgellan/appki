# Аппки

Telegram-бот и Mini App с каталогом iPhone-приложений, оплатой через ЮKassa и выдачей временных ссылок установки. Первая версия работает с одним проверенным файлом Happ 5.9.0.

## Что реализовано

- Мобильный каталог из семи приложений и прозрачная овальная корзина с общей суммой. К покупке подключён Happ; V2RayTun, Сбер, Т-Банк, ВТБ-Банк, ChatGPT и DeepSeek отмечены «Скоро» / «Готовим к запуску». Их можно посмотреть, но добавить в корзину и оплатить можно только после подключения. Перед оплатой пользователь подтверждает состав и сумму; сервер проверяет цены и сохраняет позиции заказа.
- Вход через проверенную на сервере подпись Telegram Mini App.
- ЮKassa: один платёж на весь заказ, повтор той же попытки без второго заказа, проверка статуса через API, уведомления об оплате и полном возврате. В режиме `live` открывается оплата через СБП, в `test` — тестовая форма ЮKassa.
- Доступ выдаётся только владельцу оплаченного заказа. Возврат закрывает новые установки; уже установленное приложение удалённо не удаляется.
- HTTPS-страница Safari → системная установка iOS → инструкция активации. Оригинальный IPA не изменяется и не переподписывается.
- В «Моих приложениях» показаны только подтверждённые покупки с установкой и активацией. Неоплаченные попытки сюда не попадают; покупка начинается в каталоге. Отметки «установлено» и «активировано» выставляет пользователь; приложение не проверяет запуск через Apple и не получает коды 2FA автоматически. По умолчанию активация остаётся через поддержку.
- Ссылки действуют час; новые доступны в оплаченном заказе. Поддержаны HEAD и Range для загрузки iPhone.
- Отдельный бот с командами, кнопкой Mini App и сохранением позиции обработки сообщений.
- Развёртывание на существующем VPS: nginx, systemd, отдельный пользователь, SQLite и TLS.

## Подключение аккаунтов

Заполните локальную `.env` (создаётся из `.env.example`):

| Поле | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен своего бота из BotFather |
| `BOT_USERNAME` | Username этого же бота, без `@` |
| `SUPPORT_URL` | Ссылка Telegram на поддержку |
| `YOOKASSA_SHOP_ID` | ID тестового магазина |
| `YOOKASSA_SECRET_KEY` | Секретный ключ тестового магазина, начинается с `test_` |

Цена доступа к установке — `490.00` рублей. `YOOKASSA_MODE` задаётся настройками окружения; интерфейс использует одинаковые тексты оплаты для обоих режимов. Без токенов каталог доступен для просмотра, вход и покупка отключены. Пустые значения не заменяются демонстрационными аккаунтами или фиктивной оплатой.

СБП недоступна в тестовом магазине ЮKassa: там проверяется тестовая форма с поддерживаемыми способами оплаты. Код готов создавать СБП-платежи при отдельно настроенном `live`-магазине; текущий режим сам не переключается. См. [СБП](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/manual-integration/other/sbp) и [ограничения тестового магазина](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).

В кабинете ЮKassa добавьте адрес уведомлений:

```
https://85.239.144.214/api/payments/yookassa/webhook
```

События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`. Даже без уведомления открытая карточка заказа проверяет ожидающий платёж через API. Сам переход на страницу «оплата завершена» не выдаёт доступ.

Бот после запуска сам задаёт команды и кнопку меню. В BotFather можно дополнительно настроить Main Mini App на `https://85.239.144.214/`. Если у бота уже есть чужой webhook, обработчик откажется его перезаписывать; для проекта используйте своего отдельного бота.

## Страницы и API

Каталог и корзина находятся на `/`, подробности — на `/apps/{slug}` (например, `/apps/happ` и `/apps/chatgpt`), покупки — на `/orders`, публичный раздел «Как это работает» — на `/how-it-works`. Оплата открывается на `/payment/{order_id}`, установка и активация конкретного приложения — на `/orders/{order_id}/apps/{slug}`. Сохранены страница заказа `/orders/{order_id}`, помощь `/help` и возврат из ЮKassa `/payment/return?order_id=...`.

Корзина отправляет `POST /api/orders` с `app_slugs`, `request_id` и подтверждённой `expected_amount_rub`. Сервер возвращает `items` и итог `total_rub`; при изменении цены отвечает 409 до создания платежа. Для каждой позиции доступны `POST .../items/{slug}/install-link`, `GET .../items/{slug}/activation` и `PATCH .../items/{slug}/state` внутри `/api/orders/{order_id}`. Старый запрос с `app_slug` и ссылки без позиции сохранены для заказов из одного приложения. Полные поля и правила повторов — в [контракте API](API_CONTRACT.md).

## Локальная разработка

Требуются Python 3.11+ и Node 22+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e './backend[test]'
cd web
npm ci
npm run build
cd ..
```

Серверные пути из `.env` при локальном запуске нужно переопределить:

```sh
DATABASE_PATH=./work/dev.sqlite3 STATIC_DIR=./web/dist HAPP_IPA_PATH=/absolute/path/Happ.ipa \
  .venv/bin/python -m uvicorn appki.main:create_app --factory --host 127.0.0.1 --port 18880 --no-access-log
```

Для разработки frontend: `cd web && npm run dev`. Vite перенаправляет `/api` на локальный backend. В обычном браузере работает просмотр каталога; проверяемый вход появляется только при запуске из Telegram.

## Проверки

```sh
cd backend
../.venv/bin/python -m pytest -q
cd ../web
npm test
npm run build
```

Тесты используют отдельную временную базу, синтетический IPA и поддельный транспорт API. Они не списывают деньги, не отправляют сообщения и не используют `.env` владельца. Проверяются корзина, защита подтверждённой суммы, повторы оплаты, состояния отдельных позиций и совместимость старых заказов. Тестовый платёжный цикл проверяется отдельно после подключения тестового магазина; реальная СБП требует настоящего магазина.

## Развёртывание

```sh
./scripts/deploy.sh
```

Скрипт собирает интерфейс, запускает тесты, передаёт код и закрытую `.env` через SSH, запускает службы и проверяет HTTPS. Настроен для `root@85.239.144.214` и существующего IP-сертификата Let's Encrypt. Для другого домена сначала обновите `PUBLIC_BASE_URL` и nginx/TLS.

`.env`, IPA, базы, ключи и зависимости исключены из Git. Архив релиза формируется по списку разрешённых путей; `.env` передаётся отдельно и хранится с ограниченными правами. На сервере используются `/opt/appki/current`, `/etc/appki/appki.env`, `/var/lib/appki/`.
